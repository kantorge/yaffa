# AI Document Retention — Emails

## Inventory

| Notification | Class · template | Trigger | Recipient | Subject key |
|---|---|---|---|---|
| Old AI documents waiting | `App\Mail\AiDocumentsAwaitingAction` · `resources/views/emails/ai-documents-awaiting-action.blade.php` (markdown mail) | `CleanupOldAiDocuments::handle()` when ≥ 1 non-finalized document is older than the retention cutoff | The document owner's own `users.email` | `mail.ai_documents_awaiting_action.subject` |

## Path

Job (queue worker) → `Mail::to($user->email)->locale($user->language)->send()` → configured mail transport. The Mailable uses `Queueable` + `SerializesModels` but does **not** implement `ShouldQueue`, so it is sent synchronously inside the already-queued job.

## Template inputs

| Variable | Origin | Encoding |
|---|---|---|
| `$user->name` | user profile (self-authored) | `{{ }}` escaped in the markdown component |
| `$count`, `$retentionDays` | integers computed by the job | typed `int` |
| `$url` | `route('ai-documents.index', ['status' => 'unprocessed', 'date_to' => Y-m-d])` | generated by the router, host from `APP_URL` |

No document content, file names, transaction data or received-mail text is included. The reminder says how many documents are waiting, not which.

## Translations

`lang/{en,fr,hu,pl}/mail.php` → `ai_documents_awaiting_action.*`. Locale comes from `users.language`.

## Frequency and failure behaviour

- Once per user per run; the schedule is daily, so one per day until the documents are finalized or deleted. No cap, no back-off, no per-user opt-out separate from clearing the retention period.
- Mail-transport failure throws inside the job: job fails/retries per queue policy; deletion already committed is unaffected.
- Where to look: `failed_jobs`, application log, and mail transport logs (MailHog in dev on `:8027`).
- The wording promises that "unprocessed ones are always kept" and "You will get this reminder daily until then" — both match the implementation.
